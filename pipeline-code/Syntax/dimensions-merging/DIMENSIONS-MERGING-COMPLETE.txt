DIMENSIONS AND MERGING SYNTAX - COMPLETE REFERENCE
================================================================

OVERVIEW
--------
This document describes cell merging using colspan and rowspan attributes, and column width control using col width declarations in SocialCalc format version 1.5. Cell merging combines multiple cells into a single visual cell spanning multiple columns or rows. Column width control sets pixel widths for individual columns to create professional document layouts with proper margins and spacing.

CORE SYNTAX
-----------

CELL MERGE SYNTAX
cell:COORD:t:TEXT:colspan:N
cell:COORD:t:TEXT:rowspan:N
cell:COORD:t:TEXT:colspan:N:rowspan:M

COLUMN WIDTH SYNTAX
col:LETTER:w:PIXELS

PARAMETERS
- COORD: Cell coordinate (A1, B2, etc)
- TEXT: Cell content text
- N, M: Positive integers (must be >= 1)
- LETTER: Column letter (A, B, C, etc)
- PIXELS: Width in pixels (positive integer)

MERGE ATTRIBUTES
----------------

COLSPAN (Horizontal Merge)
Spans cells horizontally across columns.
Value N means cell occupies N columns.
All cells to the right must be marked empty.

Example colspan:2
cell:A1:t:Header:colspan:2
cell:B1:t:
Result: A1 spans across A1 and B1 (2 columns total)

Example colspan:3
cell:A1:t:Title:colspan:3
cell:B1:t:
cell:C1:t:
Result: A1 spans A1, B1, C1 (3 columns total)

ROWSPAN (Vertical Merge)
Spans cells vertically across rows.
Value N means cell occupies N rows.
All cells below must be marked empty.

Example rowspan:2
cell:A1:t:Label:rowspan:2
cell:A2:t:
Result: A1 spans across A1 and A2 (2 rows total)

Example rowspan:3
cell:A1:t:Sidebar:rowspan:3
cell:A2:t:
cell:A3:t:
Result: A1 spans A1, A2, A3 (3 rows total)

COMBINED MERGE (colspan + rowspan)
Creates rectangular merged area spanning both columns and rows.
Order: colspan must come before rowspan.
All covered cells must be marked empty.

Calculation: For colspan:X rowspan:Y, mark (X × Y) - 1 cells as empty.

Example 2x2 merge
cell:A1:t:Block:colspan:2:rowspan:2
cell:B1:t:
cell:A2:t:
cell:B2:t:
Result: A1 covers A1, B1, A2, B2 (4 cells total, 3 marked empty)

Example 3x3 merge
cell:A1:t:Large:colspan:3:rowspan:3
cell:B1:t:
cell:C1:t:
cell:A2:t:
cell:B2:t:
cell:C2:t:
cell:A3:t:
cell:B3:t:
cell:C3:t:
Result: A1 covers 9 cells total, 8 marked empty

EMPTY CELL MARKING
------------------
When a cell is covered by a merge, it must be explicitly defined with empty content.
Empty cell syntax: cell:COORD:t:
The :t: separator is followed immediately by nothing or newline.
This marks the cell as occupied by the merge but not containing independent content.

Pattern for 2x2 merge at A1:
cell:A1:t:Content:colspan:2:rowspan:2  (anchor cell with content and merge attributes)
cell:B1:t:                             (empty - covered horizontally)
cell:A2:t:                             (empty - covered vertically)
cell:B2:t:                             (empty - covered diagonally)

COLUMN WIDTH CONTROL
--------------------

MARGIN COLUMN (Column A)
Always reserve column A as left margin.
Width: 25-30 pixels
Purpose: Visual spacing and professional document layout
Never place content in column A

Syntax:
col:A:w:30

CONTENT START POSITION
Content must start at cell B2.
Row 1 is reserved for top margin.
Column A is reserved for left margin.
This creates professional document spacing.

Starting position pattern:
col:A:w:30
cell:B2:t:Title

COLUMN WIDTH VALUES
Width values in pixels based on content type.

Short identifiers or numbers: 60-80 pixels
col:B:w:60

Short labels like days or quarters: 80-100 pixels
col:B:w:80

Standard text like names or dates: 100-150 pixels
col:C:w:120

Long text like addresses or titles: 150-250 pixels
col:D:w:200

Descriptions or detailed content: 250-400 pixels
col:E:w:300

Email addresses: 250-300 pixels
col:F:w:250

MULTIPLE COLUMN WIDTHS
Define width for each visible column.
Each column gets separate col declaration.

Example table with varying widths:
col:A:w:30
col:B:w:100
col:C:w:200
col:D:w:150

Example equal width columns:
col:A:w:30
col:B:w:120
col:C:w:120
col:D:w:120
col:E:w:120

MERGE CALCULATION FORMULAS
---------------------------

EMPTY CELLS REQUIRED
For merge with colspan:X rowspan:Y
Total cells in merge area: X × Y
Empty cells to mark: (X × Y) - 1

Examples:
2x1 merge: (2 × 1) - 1 = 1 empty cell
1x2 merge: (1 × 2) - 1 = 1 empty cell
2x2 merge: (2 × 2) - 1 = 3 empty cells
3x3 merge: (3 × 3) - 1 = 8 empty cells
4x2 merge: (4 × 2) - 1 = 7 empty cells
5x5 merge: (5 × 5) - 1 = 24 empty cells
10x1 merge: (10 × 1) - 1 = 9 empty cells
1x12 merge: (1 × 12) - 1 = 11 empty cells

COVERED CELLS IDENTIFICATION
For merge starting at cell with coordinate (column C, row R):
colspan:X means columns C through C+(X-1) are covered
rowspan:Y means rows R through R+(Y-1) are covered

Example: Cell B3 with colspan:3 rowspan:2
Columns covered: B, C, D (3 columns)
Rows covered: 3, 4 (2 rows)
Cells to mark empty: C3, D3, B4, C4, D4 (5 cells)

Use rowspan for category labels

Use rowspan for hierarchical row labels

ERROR PATTERNS TO AVOID
-----------------------

MISSING EMPTY CELL MARKERS
Wrong: cell:A1:t:Text:colspan:2
Missing: cell:B1:t:
Correct: Include empty cell marker for B1

WRONG EMPTY CELL COORDINATE
Wrong: cell:A1:t:Text:colspan:2 then cell:C1:t:
Correct: cell:A1:t:Text:colspan:2 then cell:B1:t:
Empty cells must be immediately adjacent to merge

INCOMPLETE EMPTY CELL COVERAGE
Wrong: cell:A1:t:Text:colspan:2:rowspan:2 then only cell:B1:t:
Missing: cell:A2:t: and cell:B2:t:
Correct: Mark all 3 cells B1, A2, B2 as empty

ZERO OR NEGATIVE VALUES
Wrong: cell:A1:t:Text:colspan:0
Wrong: cell:A1:t:Text:rowspan:-1
Correct: Use positive integers only (1 or greater)

NON-NUMERIC VALUES
Wrong: cell:A1:t:Text:colspan:two
Wrong: cell:A1:t:Text:rowspan:abc
Correct: Use numeric digits only

MISSING ATTRIBUTE VALUES
Wrong: cell:A1:t:Text:colspan
Wrong: cell:A1:t:Text:colspan:
Correct: cell:A1:t:Text:colspan:2

WRONG ATTRIBUTE ORDER
Wrong: cell:A1:t:Text:rowspan:2:colspan:3
Correct: cell:A1:t:Text:colspan:3:rowspan:2
Colspan must come before rowspan

INVALID ATTRIBUTE NAMES
Wrong: cell:A1:t:Text:columnspan:2
Wrong: cell:A1:t:Text:colmerge:2
Correct: Use colspan or rowspan exactly

TRAILING OR DOUBLE COLONS
Wrong: cell:A1:t:Text:colspan:2:
Wrong: cell:A1:t:Text::colspan:2
Correct: Single colon between attributes, no trailing colon

CONTENT IN MARGIN COLUMN
Wrong: cell:A1:t:Title
Correct: cell:B2:t:Title with col:A:w:30

STARTING AT WRONG POSITION
Wrong: cell:A1:t:Title when using margins
Correct: cell:B2:t:Title with col:A:w:30

VALIDATION RULES
----------------

COLSPAN VALIDATION
Must be positive integer
Minimum value 1 (but 1 means no merge)
Typical values 2 through 12
All horizontally covered cells must be marked empty

ROWSPAN VALIDATION
Must be positive integer
Minimum value 1 (but 1 means no merge)
Typical values 2 through 12
All vertically covered cells must be marked empty

COMBINED MERGE VALIDATION
Both colspan and rowspan must be positive integers
Colspan attribute must appear before rowspan attribute
Total covered cells (X × Y) must all be defined
Exactly (X × Y) - 1 cells must be marked empty

COLUMN WIDTH VALIDATION
Width value must be positive integer
Typical range 25 to 400 pixels
Column A should always be 25-30 pixels for margin
All visible columns should have width defined

LAYOUT VALIDATION
Column A reserved for margin (no content)
Row 1 reserved for top margin (no content)
Content starts at B2 or later
Sheet dimensions must cover all defined cells

SHEET DIMENSION VALIDATION
sheet:c:X:r:Y where X and Y are positive integers
Column count X must be >= highest column used
Row count Y must be >= highest row used
Include margin column in count

TECHNICAL SPECIFICATIONS
------------------------

FORMAT VERSION
SocialCalc format version 1.5
Line-based text format
Cell definitions one per line
Column width definitions one per line

CELL COORDINATE SYSTEM
Column: Letters A through Z, then AA, AB, etc
Row: Numbers starting at 1
Coordinate format: LETTER + NUMBER (A1, B2, AA10)

ATTRIBUTE SYNTAX
Colon-delimited key-value pairs
Format: attributename:value
Multiple attributes chained with colons
Order matters for colspan and rowspan

TEXT CONTENT
Prefix with t: for text type
Text appears between :t: and next : or end of line
Empty text: :t: with nothing after
Special characters allowed in text content

MERGE BOUNDARIES
Merges cannot overlap
Each cell can only be part of one merge
Merged cell is defined by anchor cell plus empty markers
Anchor cell contains merge attributes and content

RENDERING BEHAVIOR
Merged cell displays content from anchor cell
Empty cells in merge area display nothing
Visual boundary spans all covered cells
Content typically centered or aligned within merged area

COLUMN WIDTH BEHAVIOR
Width applies to entire column
All cells in column inherit width
Default width used if not specified
Width in pixels determines visual column size

MARGIN BEHAVIOR
Column A width creates left document margin
Row 1 creates top document margin
Margins provide visual spacing
Content never placed in margin cells

WHEN TO USE EACH FEATURE
-------------------------

USE COLSPAN WHEN:
Creating header rows that span multiple columns
Merging title cells across table width
Creating wide text entry areas
Grouping related columns under single label
Building banner or title areas
Spanning navigation items horizontally

USE ROWSPAN WHEN:
Creating sidebar labels that span multiple rows
Merging category cells down table height
Building vertical navigation menus
Creating tall logo or image areas
Grouping related rows under single category
Spanning time slots vertically in schedules

USE COMBINED MERGE WHEN:
Creating large content blocks (dashboards, cards)
Building complex layouts with multiple sections
Merging both width and height for visual emphasis
Creating grid-based designs with featured areas
Building meeting room or schedule blocks
Designing form sections or panels

USE COLUMN WIDTHS WHEN:
Creating professional document layouts
Needing different widths for different content types
Building tables with ID, name, description columns
Creating forms with labels and input areas
Designing dashboards with metrics
Establishing consistent margins and spacing

USE MARGINS WHEN:
Creating professional documents
Needing visual breathing room
Separating content from page edges
Following standard document layout practices
Building print-ready layouts
Maintaining consistent design spacing

PRACTICAL DECISION GUIDE:
Single row of merged cells: Use colspan only
Single column of merged cells: Use rowspan only
Block area spanning both dimensions: Use colspan and rowspan together
Different column needs different widths: Define column widths
Professional document: Always use column A margin
Complex layout: Combine merges with column widths
