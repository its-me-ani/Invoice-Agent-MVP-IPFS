MULTILINE INPUT SYNTAX - COMPLETE REFERENCE

PROPERTY NAME
Multiline text input using escape sequences in cell text values

ESCAPE SEQUENCE
\n - Newline character that creates line breaks within cell text content

SYNTAX STRUCTURE
cell:<cell_reference>:t:<text_with_\n_escapes>

CORE PROPERTIES
Escape sequence: \n
Cell type: t (text)
Valueformat: None (plain text cells only)
Rendering: Line breaks are rendered as actual newlines in cell display
Context: Used within text content portion of cell definition

BASIC SYNTAX PATTERNS

Pattern 1: Two lines
cell:A1:t:Line 1\nLine 2

Pattern 2: Three lines
cell:A1:t:First\nSecond\nThird

Pattern 3: Multiple lines
cell:A1:t:Line 1\nLine 2\nLine 3\nLine 4\nLine 5

Pattern 4: Blank lines between content
cell:A1:t:Paragraph 1\n\nParagraph 2\n\nParagraph 3

Pattern 5: Combined with colon separator
cell:A1:t:Name\cJohn Doe\nAge\c30\nCity\cNew York

Use Case 1: Contact information storage
Store complete address with street, city, state, zip code in single cell using line breaks to separate components

Use Case 2: List creation within cells
Create bullet lists, numbered lists, or todo lists within a single cell without needing multiple rows

Use Case 3: Multi-line labels or headers
Display headers with subtitles or descriptions where main title and supporting text need line breaks

Use Case 4: Text formatting preservation
Preserve line breaks in copied text such as poetry, song lyrics, or formatted paragraphs

Use Case 5: Structured data display
Display key-value pairs vertically within single cell using combination of colon separator and newlines

Use Case 6: Code or command display
Show code snippets, terminal commands, or script content with preserved line breaks and indentation

Use Case 7: Notes and comments
Add multi-line notes, descriptions, or annotations to cells without expanding to multiple rows

Use Case 8: Form field simulation
Create form-like structures with labels and input areas using multiline formatting

Use Case 9: Compact data presentation
Display multiple related data points in compact space using vertical stacking with line breaks

Use Case 10: Multi-line cell in tables
Create table cells containing multiple lines of information while maintaining table structure

ESCAPE SEQUENCE RULES

Rule 1: Use \n for single line break
Creates one newline between content

Rule 2: Use \n\n for blank line
Creates empty line by placing two consecutive newline characters

Rule 3: Literal backslash requires escaping
To display actual backslash character use \\ 

Rule 4: No valueformat required
Multiline text works with plain text cells (type t) without special valueformat

Rule 5: Preserve all spacing
Spaces before and after \n are preserved in rendered output

Rule 6: Works with any text content
Can be combined with any text including special characters, numbers, or symbols

Rule 7: No limit on line count
Can use unlimited \n sequences to create any number of lines within cell

Rule 8: Compatible with cell properties
Works alongside fonts, borders, backgrounds, alignment, and other cell properties

TECHNICAL SPECIFICATIONS

Escape sequence: \n (backslash followed by lowercase n)
Cell type requirement: t (text type cells only)
Value type restriction: Cannot be used in numeric cells (v type) or formula cells (f type)
Rendering behavior: Each \n converts to actual line break in visual display
Content length: No specific limit on total text length or number of line breaks
Property interaction: Compatible with all cell properties (fonts, colors, borders, alignment, padding)
Sheet dimension impact: Does not increase row count, all lines stay within single cell
Text flow: Line breaks occur at exact \n position regardless of cell width

COMMON ERRORS TO AVOID

Error 1: Missing colon before property reference
Wrong: cell:A1:t:Text\nMore:f
Correct: cell:A1:t:Text\nMore:f:1

Error 2: Starting text with newline without content
Wrong: cell:A1:t:\nContent
Better: cell:A1:t:Header\nContent

Error 3: Too many consecutive blank lines
Wrong: cell:A1:t:Text\n\n\n\nMore
Better: cell:A1:t:Text\n\nMore

Error 4: Invalid property reference after multiline text
Wrong: cell:A1:t:Text\nMore:c:99
Correct: cell:A1:t:Text\nMore:c:1

Error 5: Missing property definition for reference
Wrong: cell:A1:t:Text\nMore:cf:1 (without cellformat:1 definition)
Correct: cell:A1:t:Text\nMore:cf:1 + cellformat:1:left

Error 6: Using with non-text cell type
Wrong: cell:A1:v:100\n200
Correct: cell:A1:t:100\n200

Error 7: Invalid property abbreviation
Wrong: cell:A1:t:Text\nMore:colspan
Correct: cell:A1:t:Text\nMore:colspan:2

Error 8: Multiple invalid references
Wrong: cell:A1:t:Text\nMore:b:1:1:1
Correct: cell:A1:t:Text\nMore:b:1

Error 9: Invalid background reference
Wrong: cell:A1:t:Text\nMore:bg:99
Correct: cell:A1:t:Text\nMore:bg:1

Error 10: Invalid border combination
Wrong: cell:A1:t:Text\nMore:b:1:1 (without proper border definition)
Correct: cell:A1:t:Text\nMore:b:1 + border:1:1px solid rgb(0,0,0)

WHEN TO USE MULTILINE INPUT

Use when content naturally spans multiple lines such as addresses or lists
Use when preserving line breaks from source text like poetry or formatted documents
Use when creating compact displays with multiple data points in single cell
Use when simulating form fields with labels and multi-line values
Use when displaying code snippets or terminal output with preserved formatting
Use when creating structured content with headers and body text in one cell
Use when building tables with multi-line headers or data cells
Use when space is limited and vertical stacking is more efficient than horizontal expansion
Use when maintaining readability requires visual separation of text components
Use when copying formatted text that requires line break preservation

WHEN NOT TO USE MULTILINE INPUT

Do not use when each line represents independent data that should be in separate rows
Do not use when line-by-line analysis or filtering is required
Do not use when each line needs individual formatting different from others in same cell
Do not use in formula cells or numeric value cells
Do not use when lines need different property assignments like individual borders or backgrounds
Do not use when export to other formats requires one value per row
Do not use when sorting or grouping by individual line content is needed
Do not use when screen readers or accessibility tools need to parse lines separately
Do not use when each line represents separate database records or entities
Do not use when downstream processing expects one line per cell

PROPERTY COMPATIBILITY MATRIX

Compatible with font property: YES - Apply font to entire multiline cell
Compatible with cellformat property: YES - Apply alignment to entire multiline cell
Compatible with layout property: YES - Apply padding and vertical alignment to entire cell
Compatible with border property: YES - Border surrounds entire multiline cell
Compatible with color background: YES - Background fills entire multiline cell area
Compatible with color foreground: YES - Text color applies to all lines
Compatible with colspan property: YES - Multiline cell can span columns
Compatible with rowspan property: YES - Multiline cell can span rows
Compatible with valueformat property: NO - Multiline is plain text only
Compatible with formula type: NO - Cannot use \n in formula cells
Compatible with numeric type: NO - Only works with text type cells
Compatible with colon separator: YES - Can combine \c and \n in same cell

DATA VALIDATION RULES

Rule: Cell type must be t (text)
Rule: Property references must have corresponding definitions
Rule: Font references must point to defined font entries
Rule: Cellformat references must point to defined cellformat entries
Rule: Layout references must point to defined layout entries
Rule: Border references must point to defined border entries
Rule: Color references must point to defined color entries
Rule: Sheet dimensions must accommodate all defined cells
Rule: Escape sequences must be properly formatted as \n
Rule: Multiple properties must be separated by colons
Rule: Property reference indices must be positive integers
Rule: All referenced properties must exist before cell reference

SUMMARY

Multiline input allows text cells to contain multiple lines using \n escape sequence. Works exclusively with text type cells (type t). Compatible with all cell properties including fonts, alignment, padding, borders, colors, and spanning. Primary use cases include addresses, lists, notes, code snippets, and structured multi-line content. Cannot be used with formulas or numeric values. Renders as actual line breaks in cell display. No limit on number of lines. Can be combined with colon separator for label-value pairs. Properties apply to entire multiline cell not individual lines.
